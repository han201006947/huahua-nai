# 扫码加载稳定加速（首屏不拉 GitHub）

## 改动背景 / 需求

用户多次反馈扫码打开慢、不稳定。此前为同步准确，在 mount 时立刻强制拉 GitHub raw 大文件，导致微信内首屏卡顿。

## 策略（速度与同步兼顾）

| 阶段 | 行为 |
|------|------|
| 0～1 秒 | 品牌占位 + Hero/价目图；作品集用**打包静态数据** |
| 顾客首页 | 作品集延迟约 0.4～0.7 秒挂载（店主 `#gallery` 仍立刻） |
| 4.5 秒后 | 后台 idle 拉轻量 `revision`；**仅 rev 变化**才拉 `galleryAlbums.js` |
| 轮询 | 每 5 秒比对 revision（jsDelivr 优先，体积小） |
| 构建 | 注入 `__GALLERY_BUILD_REV__` / `latestIds`，与 deploy 包一致则**零网络** |

## 涉及文件

- `vite.config.js` — 构建注入 revision 快照
- `src/main.js` — 登录校验改后台，不 await
- `src/App.vue` — 作品集静态 import；顾客延迟挂载
- `src/components/HeroSection.vue` — 按钮先触发挂载再滚动
- `src/components/GallerySection.vue` — 取消 mount 立刻 `refreshOnlineGallery`
- `src/composables/useGalleryAlbums.js` — 构建 baseline、列表相同不重绘
- `src/utils/githubContents.js` — revision 走 fast CDN；列表走 fresh raw
- `scripts/inject-site-url.mjs` — preload app.js

## 验证

1. 顾客扫码：1 秒内应看到价目 Hero，不应长时间白屏。
2. 向下滚或点「浏览作品集」：网格正常；封面仍懒加载。
3. 店主增删后：仍即时更新；顾客 5～15 秒内后台对齐（rev 变才拉大文件）。
